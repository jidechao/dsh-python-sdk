# 发布前检查清单

按顺序执行以下检查，每项通过后在回复中标注 ✓，未通过标注 ✗ 并给出修复建议。

1. **版本号核对**：读取项目根目录的版本字段（package.json / pyproject.toml），
   与 git tag `git tag --list 'v*'` 的最新版本对比，确认本次发布的目标版本号
   符合语义化版本（semver）且未与已有 tag 冲突。

2. **变更日志**：检查 CHANGELOG.md 是否包含目标版本的条目。
   若缺失，运行 `git log <上一tag>..HEAD --oneline` 归纳变更并起草条目，
   交由用户确认后写入。

3. **工作区干净**：运行 `git status --porcelain`，确认无未提交变更。
   有未提交内容时停止发布流程并列出文件，请用户先处理。

4. **测试通过**：运行项目约定的测试命令（查看 package.json scripts 或
   pyproject.toml 确定），全部通过后继续。

5. **构建验证**：执行构建命令并确认产物存在且非空。

## 输出格式

以 Markdown 清单回复：每项一行 `✓/✗ 检查项 — 说明`，末尾给出一句话结论：
"可以发布" 或 "发布前需先处理 N 项"。
